# معايير أداء لغة عربي (الإصدار 1.30.0)

البنية المعيارية التي طلبها تقرير التدقيق العميق (الفصل 19 — «غير مقاس إطلاقًا — لا بنية معيارية واحدة»)، والمتبقِّ الموثق في سجل العمل: «معايير أداء benchmarks/».

## التشغيل

```bash
# جدول أرقام كامل (دقيقة تقريبًا)
python3 benchmarks/run.py

# وضع سريع للاختبارات وCI (ثوانٍ)
python3 benchmarks/run.py --quick

# بوابات الانحلال (تكافؤ + نسب + سقوف) — يخرج برمز 1 عند فشل أي بوابة
python3 benchmarks/run.py --check

# مقارنة صارمة 50% مقابل خط أساس جهاز مرجعي (بوابة الإصدار على نفس الجهاز)
python3 benchmarks/run.py --baseline benchmarks/baseline.json

# إخراج آلي + تسجيل خط أساس جديد
python3 benchmarks/run.py --json
python3 benchmarks/run.py --save-baseline benchmarks/baseline.json
```

## المعايير الخمسة وما يقيسه كل منها

| المعيار | الحمل | ماذا يقيس | لماذا (مصدره في التدقيق) |
|---|---|---|---|
| `بدء` | عملية بايثون كاملة: استيراد + تحليل + تنفيذ «اطبع(1+1)» | زمن البدء البارد من الصفر | الفصل 19: لا قياس لزمن بدء المفسر |
| `حلقة_ساخنة` | مليون تكرار داخل دالة (المعيار التاريخي منذ 1.22) | الدولاب مقابل الشجري + نسبة التسريع | الفصل 9/19: معيار التكافؤ والأداء المرجعي |
| `مولدات` | مولد «أنتج» يجمّع مدى(٢٠٠ ألف) | المسار الشجري دائمًا (حد الموثق منذ 1.13) | الفصل 19(أ): المولدات تتجاوز الدولاب — متابعة |
| `بيئة_قدّم` | ترميز بيئة الجذر بحجمين (٢٠٠ و٢٠٠٠ متغيرًا) | كلفة O(globals) عند كل قدّم | الفصل 19(ج): كل قدّم يعيد ترميز البيئة كاملة |
| `تشفير` | شفّر/فكّ نص ١ ميجابايت بمفتاح ثابت | نفاذية ميجابايت/ثانية لكل اتجاه | الفصل 19(د): AEAD بايثون-صافٍ — متابعة النفاذية |

## فلسفة البوابات (لماذا لا تُقارن CI بأرقام مطلقة؟)

أجهزة CI تختلف جوهريًا، فالمقارنة المطلقة تهشّ. لذلك طبقتان:

1. **بوابات داخلية (`--check`) — تعمل في أي بيئة:**
   - تكافؤ النتائج: ناتج الدولاب = ناتج الشجري = ن(ن-١)/٢ المشتق رياضيًا، مفحوص في كل دورة قياس.
   - نسبة التسريع: الدولاب ألا يكون أبطأ من الشجري × 1.5 (حد انحلال 50% — المطلوب حرفيًا في التدقيق).
   - سقوف كارثية: كل معيار له سقف مطلق بعشرات الأضعاف عن القياس الفعلي — يكشف الانحلال القطعي (انفجار ×10) دون إزعاج أجهزة بطيئة.
2. **خط أساس الجهاز المرجعي (`--baseline`) — بوابة الإصدار على جهاز المطور:** انحلال أي رقم >50% مقابل `baseline.json` يفشل. الأرقام المسجلة عند إصدار 1.30.0 (بايثون 3.12):

| الرقم | القيمة |
|---|---|
| بدء عملية كاملة | 0.14 ثانية |
| حلقة المليون — دولاب | 1.63 ثانية |
| حلقة المليون — شجري | 2.38 ثانية |
| نسبة التسريع | 1.43–1.46× |
| مولد ٢٠٠ ألف عنصر | 8.0 ثانية |
| ترميز بيئة ٢٠٠٠ متغيرًا | 0.002 ثانية |
| تشفير/فك | 3.8 / 3.78 ميجابايت/ثانية |

## الحدود الموثقة التي تتابعها هذه المعايير (لا تُخفى)

- المولدات دائمًا شجرية — معيار `مولدات` يقيسها ليكشف أي انحلال، والانتقال للدولاب بند مستقبلي موثق لا وعد صامت.
- نفاذية التشفير ~3.8 ميجابايت/ثانية بايثون-صافٍ — التدقيق لاحظ أنها بطيئة نسبيًا؛ المعيار يجعل أي ترقية مستقبلية (بلوكات أكبر/مكتبة قياسية) قابلة للقياس قبل وبعد.
- ترميز البيئة خطي في حجم الجذر — المعيار يثبت الخطية ويكشف أي انفجار.

## ملاحظات منهجية

- كل قياس = **وسيط 3 دورات** (البدء 7 في الوضع الكامل) — الوسيط مقاوم للشوائب دون تزيين.
- كل دورة تتحقق من النتيجة الرياضية قبل قبول زمنها — زمن بلا صحة ليس معيارًا.
- المعايير بيضاء-الصندوق في موضعين موثقين فقط (`_encode_root` و`_crypto_encrypt/decrypt` مباشرة) لتعزيز الضجيج عن استدعاءات اللغة — الكل بلا شبكة ولا كتابة خارجية.
- سقف المولدات الكامل 30 ثانية هو سقف كارثي (القياس الفعلي 8.0 ثانية — ×4 هامش)، لا سقف حاد؛ الحدة الحقيقية في `--baseline`.
